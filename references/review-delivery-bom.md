## 审核等级

对每个要求使用以下状态之一：

- `通过`：可由模型或导出文件直接验证，结果在允许差值内。
- `名义值通过`：基本尺寸正确，但公差、表面或工艺能力没有由 CAD 验证。
- `需人工/计量确认`：需要检具、量具、材料证明、热处理记录或工艺人员判断。
- `失败`：模型、导出或数据与要求不符。

审核报告必须明确总体结论，且不得用“通过”概括仍存在的失败或阻塞项。

## 几何审核清单

- 强制重建无错误；所有关键特征未压缩、未悬空。
- 实体/曲面数量符合设计意图，没有意外多实体或零厚度几何。
- 包围盒与总体尺寸一致；旋转件轴向和径向方向没有交换。
- 关键孔、槽、台阶、齿数、阵列数量、偏置和贯穿条件一致。
- 基准面、轴和特征名称可读，草图具备必要约束。
- 原生文件和 STEP 保存错误码、警告码为零，文件大小非零。
- STEP 重新打开后仍是预期数量的闭合实体。
- 等轴测、正视、侧视图片清晰、无遮挡、无截断。
- 正面、侧面、俯视、3D 和剖面五视图均已输出，并与参考图建立逐项对照表。

装配体还必须检查：

- 组件数量、配置、抑制/轻化状态与 BOM 一致；
- 功能基准和装配包围盒正确，零件修订后没有因包围盒变化而漂移；
- 应贴合的面在完整厚度/长度范围内接触，不仅在单一剖面或中心线相切；
- 不应接触的位置没有穿透，焊接接触与实体焊道的表达边界已披露；
- 修改几何后重新读取质量属性并刷新 BOM，不沿用旧质量。
- 单零件修订后，未修改零件哈希与修订前一致；错误零件只在候选件和重装配全部通过后删除。
- 默认交付只保留一个有效模型集；项目根目录、历史目录、候选目录和旧零件目录不得残留模型格式文件。

工程图剖视还必须检查：

- 剖切线穿过目标实体且方向与参考图一致；
- 保存并重新打开工程图后，剖视对象、剖切线和有效面剖面填充仍存在；
- 轴、杆、销和紧固件按图示约定不剖时无剖面线；
- 剖面没有重叠、倒置、裁切或把相邻零件误合并为同一填充区域。

## 质量属性

- 从最终重建后的配置读取质量、体积、表面积、重心和材料密度。
- 记录配置名和材料来源。材料为近似牌号或仅手动密度时，重量标为“理论值”。
- 单位统一：质量 kg、体积 cm³、面积 m² 或 mm²，并在字段名中注明。
- 装配体 BOM 使用与数量归并相同配置的质量属性。

## BOM 规则

### 单件零件

至少包含：

| 字段 | 来源 |
|---|---|
| 项次 | 顺序编号 |
| 零件号 | 图签或自定义属性 |
| 名称 | 图签或自定义属性 |
| 规格/型号 | 关键功能参数摘要 |
| 数量 | 用户/装配需求，默认 1 需可编辑 |
| 单位 | 件、套等 |
| 材料/牌号 | 图纸材料 |
| 单重 | SolidWorks 质量属性 |
| 总重 | 公式 `数量 × 单重` |
| 来源文件 | SLDPRT 文件名和配置 |
| 备注 | 热处理、精度、理论材料等 |

### 装配体

- 按零件号 + 配置归并，不仅按文件名归并。
- 区分自制件、标准件、外购件、虚拟件和参考件。
- 明确抑制、轻化、排除 BOM 和包络组件的处理。
- 对子装配按用户要求选择“整体一行”或“展开到零件”；选择必须在聊天窗口说明。

### Excel 结构

优先生成：

1. `BOM`：物料行、数量、单重和公式总重。
2. `技术参数`：图纸值、名义值、公差/等级、模型实现和备注。
3. `检验要求`：检验项目、标准/代号、允许值、模型表达和建议方法。

对工作簿执行公式错误扫描并渲染每张工作表。若只能输出 CSV，使用 UTF-8 编码并在聊天窗口说明缺失的样式、公式或多工作表能力。

## 推荐交付目录

```text
<confirmed-output>/
├── <base>.SLDPRT 或 <base>.SLDASM
├── <base>.STEP
├── <base>_等轴测.png
├── <base>_正视.png
├── <base>_侧视.png
├── <base>_俯视.png
├── <base>_A-A剖视.png
├── <base>_五视图对图报告.md
├── <base>_模型审查数据.json
├── <base>_图纸审核报告.md
├── <part-number>_BOM.xlsx
├── <base>_生成日志.txt
├── delivery_manifest.json
└── SHA256.txt
```

重建源代码和编译工具放入独立子目录，避免与主交付件混杂。不要把安装目录中的 interop DLL 提交到 GitHub。

若 STEP 导出失败：保留成功保存的 SLDPRT/SLDASM、预览和审查数据，但交付状态必须为“未就绪”或“有条件”；旧 STEP 只能放入历史目录，不能冒充当前修订版。

### 项目级唯一模型门禁

在最终回复前运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File scripts/Test-SolidWorksDelivery.ps1 `
  -OutputDirectory '<project-root>\<final-directory>' `
  -ProjectRoot '<project-root>' `
  -RequireNoModelsOutsideOutput `
  -BaseName '<base>' -DocumentType Assembly -AsJson
```

`ModelSetHygiene.OutsideModelCount` 必须为 `0`，且 `Ready` 必须为 `true`。旧图片、日志、JSON 和源代码可以保留追溯；旧 `SLDPRT/SLDASM/SLDDRW/STEP/STP` 默认不能留在最终目录外。用户明确要求保留历史模型时，取消此硬门禁并在聊天窗口完整披露。

## 最终聊天输出

最终回复至少包含：

- 已生成并实际验证的文件路径；
- 模型的可编辑性、SolidWorks 版本和交换格式；
- 名义几何审核结论和理论质量；
- `技能外事项 / 待确认`：缺失尺寸、假设、未实体化要求、人工检验、API/工具限制和失败项；
- 是否适合课程展示、装配检查、3D 打印或正式加工。正式加工必须保留工艺和计量复核条件。

任何未出现在本参考中的新交付类型、标准解释、第三方插件或制造判定，都必须先在聊天窗口披露。
